Ask the retail data

Type a business question. The agent writes the SQL, checks it against guardrails, runs it on 86,904 retail order items inside your browser, fixes its own query if it fails, and answers with the number, a chart and the SQL behind it.

TheLook e-commerce, 2023–2025 · same tables and KPI definitions as the retail performance pack · scored 19/20 on a 20-question test · code, tests and evaluation on GitHub

How each answer is produced

1 · Semantic layerThe three tables and one definition per KPI (net sales, margin, AOV, return rate…) go with every question, so the model never invents a business rule.
2 · Model writes SQLReturns JSON: the query, a chart suggestion and any assumption it made.
3 · GuardrailsSingle read-only SELECT, known tables only, row cap. Anything else is rejected and sent back.
4 · Runs in your browserSQLite (sql.js) on the same 86,904 rows. Nothing leaves your machine except the model call.
5 · Self-correctionA rejected or failing query goes back to the model with the error, up to three attempts.
6 · Answer from the result onlyThe written answer may use only the numbers in the table, and the SQL is always shown.

The 19/20 evaluation ran the Python version of this agent on DuckDB with Claude Sonnet 5.5; this page is the same design ported to SQLite so it can run with no server. Live mode uses a small daily budget and may say no when it's used up. The data is Google's public TheLook dataset, a fictional retailer.
